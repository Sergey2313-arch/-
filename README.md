# ReviMarket

[![ReviMarket .NET CI](https://github.com/Sergey2313-arch/-/actions/workflows/dotnet-ci.yml/badge.svg)](https://github.com/Sergey2313-arch/-/actions/workflows/dotnet-ci.yml)

**ReviMarket** — учебный full-stack marketplace / freelance-платформа на **ASP.NET Core MVC и .NET 8**.

Проект развивается как портфолио-приложение: пользователи могут создавать аккаунты, работать с каталогом заказов и цифровых услуг, общаться внутри платформы и управлять данными через личный кабинет.

> Текущее имя репозитория `-` временное. Для портфолио рекомендуется переименовать его в `revimarket`.

## Основной стек

- C#;
- .NET 8;
- ASP.NET Core MVC;
- ASP.NET Core Identity;
- Entity Framework Core;
- SQLite;
- Razor Views;
- xUnit;
- GitHub Actions;
- HTML, CSS и JavaScript.

## Возможности

- регистрация и авторизация пользователей;
- уникальные аккаунты по email;
- роли пользователей;
- каталог заказов, услуг и цифровых товаров;
- создание и управление публикациями;
- личный кабинет;
- внутренняя переписка;
- административные сценарии;
- адаптивный интерфейс;
- хранение данных через Entity Framework Core;
- EF Core migrations и автоматическая инициализация тестовых данных;
- атомарное резервирование и перечисление внутренних средств;
- защита от повторной обработки сделок и демо-платежей;
- автоматическая Release-сборка и тесты в CI.

## Локальный запуск

Требования:

- .NET 8 SDK;
- Git.

```bash
git clone https://github.com/Sergey2313-arch/-.git
cd -/src/ReviMarket.Web
dotnet restore
dotnet run
```

По умолчанию приложение использует SQLite:

```text
Data Source=revimarket.db
```

При первом запуске применяются EF Core migrations, создаются роли и тестовые публикации.

## Тесты

```bash
dotnet test tests/ReviMarket.Web.Tests/ReviMarket.Web.Tests.csproj
```

Тесты проверяют ключевые ограничения целостности: один кошелёк на пользователя, одну сделку на заказ, уникальность идентификатора платежа и валидацию бюджета заказа.

## Платежи

Встроенное пополнение является только демонстрационным и доступно исключительно в окружении `Development`. В production приложение не позволяет начислять тестовый баланс. Реальный платёжный провайдер в репозитории не подключён.

## Конфигурация и безопасность

Секреты, платёжные ключи и production-настройки не должны храниться в Git. Для локальной разработки используйте переменные окружения или User Secrets.

Identity настроен на пароль длиной от 10 символов с цифрой, строчными и заглавными буквами. После пяти неудачных попыток вход блокируется на 15 минут. Подтверждение email можно включить настройкой:

```json
{
  "Identity": {
    "RequireConfirmedEmail": true
  }
}
```

Включать эту настройку следует после подключения сервиса отправки писем и интерфейса подтверждения email.
